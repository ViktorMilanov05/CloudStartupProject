# Deployment Guide — Planify (Task & Process Management)

## Prerequisites

| Component | Minimum Version |
|---|---|
| .NET Runtime | 10.x |
| SQL Server | 2019+ (or Express) |
| Node.js | 18+ (build only, not needed at runtime) |
| IIS or NGINX | For reverse proxy |

---

## 1. Build

### Backend (API)

```bash
cd src/API
dotnet publish -c Release -o ../../publish/api
```

This produces a self-contained deployment in `publish/api/`.

### Frontend (React SPA)

```bash
cd src/Web
npm ci
npm run build
```

This produces static files in `src/Web/dist/`. Copy these to a directory the reverse proxy can serve (e.g., `publish/wwwroot/`).

```bash
# Copy build output
cp -r src/Web/dist/* publish/wwwroot/
```

---

## 2. Database Setup

1. Create a SQL Server database (e.g., `Planify`).
2. Apply EF Core migrations:

```bash
cd src/API
dotnet ef database update --connection "Server=YOUR_SERVER;Database=Planify;Trusted_Connection=true;TrustServerCertificate=true;"
```

Or use a migration bundle for environments without the SDK:

```bash
dotnet ef migrations bundle -o efbundle.exe
./efbundle.exe --connection "YOUR_CONNECTION_STRING"
```

## 3. Configuration

Create `appsettings.Production.json` in the API publish directory:

```json
{
  "ConnectionStrings": {
    "Default": "Server=YOUR_SERVER;Database=Planify;Trusted_Connection=true;TrustServerCertificate=true;"
  },
  "Jwt": {
    "Secret": "GENERATE-A-RANDOM-256-BIT-KEY-HERE-REPLACE-THIS!",
    "Issuer": "Planify",
    "Audience": "Planify",
    "AccessTokenExpirationMinutes": 30,
    "RefreshTokenExpirationDays": 7
  },
  "FileStorage": {
    "BasePath": "D:\\AppData\\Planify\\Attachments",
    "MaxFileSizeMB": 25
  },
  "Cors": {
    "AllowedOrigins": ["https://planify.yourcompany.com"]
  }
}
```

### Key Configuration Notes

- **JWT Secret**: Generate a random 256-bit key. Example: `openssl rand -base64 32`
- **FileStorage.BasePath**: Must be an absolute path, outside the web root. Ensure the app pool identity has read/write permissions.
- **CORS Origins**: Set to the exact URL where the frontend is served. No trailing slash.

## 4. IIS Setup (Windows)

### API (Reverse Proxy to Kestrel)

1. Install the [.NET Hosting Bundle](https://dotnet.microsoft.com/download/dotnet/10.0)
2. Create a new IIS site pointing to the `publish/api` directory
3. Set the application pool to **No Managed Code**
4. The `web.config` generated by `dotnet publish` configures the ASP.NET Core module automatically

### Frontend (Static Files)

1. Create a separate IIS site (or virtual directory) for the frontend
2. Point it to `publish/wwwroot/`
3. Add URL Rewrite rules for SPA routing (all non-file requests → `index.html`):

```xml
<!-- web.config for frontend -->
<configuration>
  <system.webServer>
    <rewrite>
      <rules>
        <rule name="SPA Fallback" stopProcessing="true">
          <match url=".*" />
          <conditions logicalGrouping="MatchAll">
            <add input="{REQUEST_FILENAME}" matchType="IsFile" negate="true" />
            <add input="{REQUEST_FILENAME}" matchType="IsDirectory" negate="true" />
            <add input="{REQUEST_URI}" pattern="^/api" negate="true" />
            <add input="{REQUEST_URI}" pattern="^/hubs" negate="true" />
          </conditions>
          <action type="Rewrite" url="/index.html" />
        </rule>
        <rule name="API Proxy" stopProcessing="true">
          <match url="^api/(.*)" />
          <action type="Rewrite" url="http://localhost:5000/api/{R:1}" />
        </rule>
        <rule name="SignalR Proxy" stopProcessing="true">
          <match url="^hubs/(.*)" />
          <action type="Rewrite" url="http://localhost:5000/hubs/{R:1}" />
        </rule>
      </rules>
    </rewrite>
  </system.webServer>
</configuration>
```

## 5. NGINX Setup (Linux)

```nginx
server {
    listen 443 ssl http2;
    server_name planify.yourcompany.com;

    ssl_certificate     /etc/ssl/certs/planify.crt;
    ssl_certificate_key /etc/ssl/private/planify.key;

    # Frontend static files
    root /var/www/planify/wwwroot;
    index index.html;

    # SPA fallback
    location / {
        try_files $uri $uri/ /index.html;
    }

    # API reverse proxy
    location /api/ {
        proxy_pass http://localhost:5000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection keep-alive;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }

    # SignalR WebSocket proxy
    location /hubs/ {
        proxy_pass http://localhost:5000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

# HTTP → HTTPS redirect
server {
    listen 80;
    server_name planify.yourcompany.com;
    return 301 https://$server_name$request_uri;
}
```

## 6. First Run

1. Start the API application
2. Navigate to the frontend URL in a browser
3. You will be redirected to the **Setup** page
4. Create the initial admin account (email + password)
5. You are now logged in as Admin
6. Navigate to the **Companies** page to create companies and their managers
7. Managers can then create users and templates within their company

## 7. Running as a Service

### Windows (NSSM or Windows Service)

```powershell
# Using NSSM:
nssm install Planify "C:\publish\api\API.exe"
nssm set Planify AppDirectory "C:\publish\api"
nssm set Planify AppEnvironmentExtra "ASPNETCORE_ENVIRONMENT=Production"
nssm start Planify
```

### Linux (systemd)

```ini
# /etc/systemd/system/planify.service
[Unit]
Description=Planify API
After=network.target

[Service]
WorkingDirectory=/var/www/planify/api
ExecStart=/var/www/planify/api/API
Restart=always
RestartSec=10
Environment=ASPNETCORE_ENVIRONMENT=Production
Environment=ASPNETCORE_URLS=http://localhost:5000

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable planify
sudo systemctl start planify
```

## 8. File Storage

- Attachments are stored at the path configured in `FileStorage:BasePath`
- Ensure the directory exists and the app has read/write permissions
- Recommended: place on a drive with adequate space, outside the application directory
- Back up this directory regularly alongside database backups

---

## 9. Troubleshooting

| Issue | Solution |
|---|---|
| 502 Bad Gateway | API is not running. Check service status and logs. |
| Login redirects to /setup | No admin user exists. Complete first-run setup. |
| SignalR fails to connect | Ensure WebSocket proxying is enabled in IIS/NGINX. |
| File upload fails | Check `FileStorage:BasePath` permissions and disk space. |
| CORS errors | Verify `Cors:AllowedOrigins` matches the exact frontend URL. |

Logs are written to `Logs/log-{date}.txt` in the API directory.
